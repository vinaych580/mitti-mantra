1. TECH STACK
================================================================================

  Backend Framework     : FastAPI (>=0.110) with Uvicorn ASGI server
  Data Validation       : Pydantic v2 (request/response models with validators)
  ML / AI               : scikit-learn (>=1.3.0)
                          - RandomForestRegressor     (yield prediction)
                          - GradientBoostingRegressor (price forecasting)
                          - RandomForestClassifier    (crop recommendation)
                          - RandomForestClassifier    (crop disease, on HSV +
                            texture features extracted from leaf photos)
  Numerical Computing   : NumPy (>=1.24,<2.5), pandas (>=2.0)
  Image Handling        : Pillow (>=10.0) — leaf-photo feature extraction
  Model Serialization   : joblib (save/load .joblib model files)
  Data Storage          : CSV flat files (9 datasets in /dataset/)
  Frontend              : Vanilla HTML + JavaScript (no framework, no build step)
  Frontend Styling      : Hand-written design system in frontend/style.css
                          (~110 KB plain CSS + custom properties).
                          NOT Tailwind — there is no CSS framework and no CSS
                          build. The only remote stylesheet is Google Fonts
                          (Fraunces + Inter).
  Frontend CDN libs     : Three.js 0.160 (globe), Chart.js 4.4 (charts),
                          Leaflet 1.9 + leaflet-draw + Turf 7 (maps/polygons)
  API Protocol          : REST (JSON over HTTP)
  CORS                  : FastAPI CORSMiddleware, allow-list from CORS_ORIGINS
                          (defaults to localhost:8000 / 127.0.0.1:8000 only)
  Static File Serving   : FastAPI StaticFiles (frontend mounted at /)
  Python Version        : No minimum pinned in requirements.txt; the checked-in
                          venv runs 3.12
  Package Management    : pip + requirements.txt
  Version Control       : Git

3. ML MODELS - DETAILS
================================================================================

  All figures below are read from ml/models/manifest.json, which is rewritten
  by ml/train_models.py (and ml/training/disease_model.py) on every training
  run. Treat that file as the source of truth; the numbers here are a snapshot
  of the currently shipped .joblib artifacts.

  3.1 Yield Prediction Model
  --------------------------
  Algorithm   : RandomForestRegressor
                (n_estimators=200, max_depth=12, min_samples_split=5,
                 min_samples_leaf=3, random_state=42)
  Features    : crop_encoded, region_encoded, season_encoded, base_yield,
                water_requirement, temp_min, temp_max, NPK requirements (N,P,K),
                soil_pH, soil_N, soil_P, soil_K, organic_carbon,
                rainfall, avg_temp, min_temp, max_temp, irrigation_level
  Total features : 20
  Training data  : 14,777 samples — yield_history x crop_parameters x soil x
                   weather, plus synthetic severe-climate-mismatch rows, then
                   6x augmentation with +/-10% uniform noise on numeric
                   features (encoded indices left intact).
  Train/Test     : 80/20 split — 11,821 train / 2,956 test
  Metrics        : R^2 = 0.8115, MAE = 763.73 kg/acre, RMSE = 2407.44 kg/acre
  Top features   : season (55.2%), rainfall (9.2%), base_yield (8.8%),
                   NPK_P (4.2%), NPK_N (2.4%), avg_temp (2.0%)
  Fallback       : If model unavailable, uses heuristic formula from
                   utils/calculations.py (soil_factor * climate_factor * base_yield)
                   adjusted by historical yield averages.

  3.2 Price Forecasting Model
  ---------------------------
  Algorithm   : GradientBoostingRegressor
                (n_estimators=300, max_depth=6, learning_rate=0.05,
                 min_samples_split=5, random_state=42)
  Features    : crop_encoded, region_encoded, month, year_offset,
                lag_1, lag_2, lag_3 (past 3 price points),
                rolling_mean_3, rolling_std_3, price_range
  Total features : 10
  Training data  : 2,223 samples — sliding windows over the 2,868 mandi price
                   rows, grouped by region x crop.
  Train/Test     : 80/20 split — 1,778 train / 445 test
  Metrics        : R^2 = 0.9118, MAE = Rs 5.07/kg, RMSE = Rs 19.65/kg
  Top features   : rolling_mean_3 (27.2%), rolling_std_3 (21.1%),
                   lag_1 (18.5%), price_range (16.2%), lag_3 (11.8%),
                   lag_2 (4.6%)
  Usage          : Iterative multi-step forecasting — each prediction is fed back
                   as a lag feature for the next month's prediction.
  Fallback       : Seasonal decomposition + linear trend extrapolation.

  3.3 Crop Recommendation Model
  -----------------------------
  Algorithm   : RandomForestClassifier
                (n_estimators=200, max_depth=10, min_samples_split=4,
                 random_state=42)
  Features    : region_encoded, season_encoded, soil_pH, soil_N, soil_P,
                soil_K, organic_carbon, rainfall, avg_temp, min_temp,
                max_temp, budget, irrigation_level
  Total features : 13
  Training data  : 60,000 samples — a synthetic grid of 500 samples per
                   region x season combination, each labelled with the best
                   crop by multi-factor scoring, plus light noise augmentation.
  Train/Test     : 80/20 stratified split — 48,000 train / 12,000 test
  Metrics        : Accuracy = 92.59%, 12 crop classes
  Top features   : rainfall (76.1%), season (13.5%), budget (4.2%),
                   min_temp (0.8%), avg_temp (0.8%), max_temp (0.7%)
  Usage          : predict_proba gives per-crop confidence scores which are
                   blended into the smart_score ranking (15% weight).
  Fallback       : Heuristic scoring (ROI + risk + budget fit + soil health).

  3.4 Crop Disease Classifier
  ---------------------------
  Algorithm   : RandomForestClassifier over 12 hand-engineered image features
                (hue histogram buckets, saturation/value means, hue mean,
                 texture score, lesion fraction) extracted by
                 engine/disease_features.py — not a CNN.
  Total features : 12
  Training data  : 539 leaf photos — 404 train / 135 test, 18 classes across
                   maize, potato, soybean and tomato.
  Metrics        : Test accuracy = 71.85%, macro-F1 = 0.7038,
                   5-fold CV mean accuracy = 67.71%
  Top features   : hue_mean (14.3%), hue_dark (11.2%), texture_score (10.3%),
                   hue_gray (9.3%), hue_brown (9.1%), val_mean (8.4%)
  IMPORTANT      : Per the note recorded in manifest.json, this is trained on a
                   small real-photo sample from the public PlantVillage research
                   benchmark — a curated academic dataset shot under controlled
                   conditions, NOT this platform's own field photos. Treat the
                   accuracy as a lab-bench figure, not field performance.
  Fallback       : The hand-tuned HSV heuristic remains the fallback whenever the
                   model file is unavailable. Both paths carry the same
                   "not a diagnosis" disclaimer at inference time.

  3.5 End-to-end Validation
  -------------------------
  ml/models/validation_report.json records a recommendation smoke test across
  five representative region/season pairs (punjab_ludhiana rabi, mh_nashik
  kharif, tn_thanjavur kharif, up_lucknow rabi, guj_anand kharif).
  Current status: 5/5 PASS, ml_used = true on every case, latency 132-269 ms.

  3.6 A note on the other metric files
  ------------------------------------
  Two further files in ml/models/ are written by separate harnesses and will
  NOT match manifest.json — they are different runs, not the shipped numbers:

    - audit_metrics.json      (ml/audit_models.py) — permutation importances
                              and robustness probes, e.g. yield R^2 holds at
                              0.9896 under a drought perturbation and
                              recommendation accuracy drops to 0.8299 under
                              noisy weather.
    - evaluation_manifest.json (ml/evaluate_models.py) — a RandomForest vs
                              CatBoost bake-off. CatBoost wins the
                              recommendation task there (0.9601 test accuracy
                              vs 0.9375), but CatBoost is NOT in
                              requirements.txt and the shipped
                              recommend_model.joblib is the RandomForest
                              recorded in manifest.json.

  GET /api/ml/status merges these audit and evaluation files into its response,
  so its output intentionally reports more than the training manifest alone.


4. HOW ML IS APPLIED (INTEGRATION FLOW)
================================================================================

  4.1 Yield Prediction
      User calls /api/simulate or /api/recommend
      -> predict_yield_kg_per_acre() in ml/predict.py
      -> Tries ML model first: builds 20-feature vector, calls model.predict()
      -> If ML unavailable or returns <=0: falls back to heuristic formula
      -> Result is used in profit calculation, simulation output, and ranking

  4.2 Price Forecasting
      User calls /api/price-forecast/{region}/{crop}
      -> price_forecast() in engine/features.py
      -> For each future month: calls _ml_predict_price() with lag features
      -> Predicted price is appended to rolling window for next step (autoregressive)
      -> If ML unavailable: uses seasonal index * linear trend extrapolation
      -> Response includes prediction_source field ("ml_model" or "heuristic")

  4.3 Crop Recommendation
      User calls /api/recommend or /api/crop-comparison
      -> recommend_crops() in ml/predict.py
      -> Calls _ml_recommend_crop() to get per-crop probability vector
      -> ML confidence is blended into smart_score (15% weight on top of
         ROI, risk, budget fit, and soil health scores)
      -> Each crop entry includes ml_confidence and prediction_source fields

  4.4 Model Retraining
      An administrator calls POST /api/ml/train
      -> Gated: requires ENABLE_MODEL_TRAINING=true AND a matching X-Admin-Key
         header against ADMIN_API_KEY (403 / 503 / 401 respectively otherwise)
      -> Runs train_all() from ml/train_models.py
      -> Rebuilds the 3 tabular models from current CSV data (the disease
         classifier is trained separately via ml/training/disease_model.py)
      -> Saves new .joblib files + updates manifest.json
      -> Next request will load fresh models automatically


5. COMPLETE FEATURE LIST (59 API ENDPOINTS)
================================================================================

  59 route handlers in total: 50 declared in backend/main.py plus 9 in
  backend/routers/data.py, which is mounted with prefix="/api". That is 58
  distinct paths — /api/crop is registered for both GET and POST.

  ---- Core Data (backend/routers/data.py) ----

  5.1  List All Crops                GET  /api/crops
       Returns all 32 crop parameter rows from crop_parameters.csv.

  5.2  Single Crop Details           GET  /api/crops/{crop_id}
       Returns detailed parameters for one crop. 404 if unknown.

  5.3  List Regions                  GET  /api/regions
       Returns the 30 distinct region_ids from soil.csv as {id, name}, with
       the id prettified for display ("mp_sehore" -> "MP · Sehore").

  5.4  Weather Data                  GET  /api/weather/{region_id}?season=kharif
       Returns rainfall and temperature data for a region, optionally filtered
       by season. Returns the most recent matching row.

  5.5  Soil Data                     GET  /api/soil/{region_id}
       Returns NPK levels, pH, organic carbon, soil type.

  5.6  Mandi Prices                  GET  /api/mandi-prices/{region_id}?crop_id=rice
       Returns raw mandi price history for a region (optionally filtered by crop).

  5.7  Yield History                 GET  /api/yield-history/{region_id}?crop_id=rice
       Returns historical yield data by crop and year.

  5.8  Yield Trend                   GET  /api/yield-trend/{region_id}/{crop_id}
       Historical yield sorted by year with year-over-year growth percentage,
       plus avg / min / max.

  5.9  Satellite Telemetry           GET  /api/satellite?lat=..&lon=..
       30-day NDVI from Google Earth Engine / Sentinel-2 with a canopy grade.
       Returns {available: false} when Earth Engine is not configured.

  ---- Core Simulation ----

  5.10 Health Check                  GET  /api/health
       Returns server status.

  5.11 Full Simulation               POST /api/simulate
       Accepts crop, area, soil, weather, input costs, irrigation.
       Returns: yield, cost breakdown, profit, ROI, risk score, water efficiency,
       nutrient gap analysis, sensitivity matrix (price x yield +-10/20%).
       Uses ML yield model internally.

  5.12 Compare Strategies            POST /api/compare-strategies
       Accepts list of strategies, runs simulation on each, returns ranked results.

  5.13 Smart Crop Recommendations    POST /api/recommend
       ML-powered: returns top-K crops ranked by smart_score (blending ML
       confidence, ROI, risk, budget fit, soil health). Each entry shows
       prediction_source and ml_confidence.

  5.14 Batch Simulation              POST /api/batch-simulate
       Simulate multiple crops simultaneously. Returns all results sorted by profit.

  5.15 Optimal Crop Mix              POST /api/optimal-mix
       Multi-crop allocation optimizer: given total area + budget, allocates
       across crops to maximize total profit.

  5.16 Crop Comparison               GET  /api/crop-comparison/{region_id}/{season}
       Compares every crop for one region/season with full metrics in one call.

  5.17 Location Insights             GET  /api/location-insights/{region_id}
       Region-level summary used to prime the dashboard for a chosen location.

  ---- Market Intelligence ----

  5.18 Mandi Price Analytics         GET  /api/price-analytics/{region_id}/{crop_id}
       Computes: average price, volatility, trend (rising/falling/stable),
       3-month moving average, seasonal monthly pattern, best/worst selling month.

  5.19 MSP Database                  GET  /api/msp?crop_id=rice&year=2025
       Returns Minimum Support Price data from msp_prices.csv (36 rows,
       18 crops).

  5.20 MSP vs Market Comparison      GET  /api/msp-vs-market/{region_id}/{crop_id}
       Compares latest MSP with current mandi price. Shows premium/discount
       percentage and recommends sell at market or sell at MSP.

  5.21 Best Time to Sell Advisor     GET  /api/sell-advisor/{region_id}/{crop_id}
       Analyzes seasonal price patterns. Returns hold/sell/partial-sell advice
       with best month to sell, expected price gain if farmer holds.

  5.22 Price Forecast (ML-powered)   GET  /api/price-forecast/{region_id}/{crop_id}?months_ahead=6
       ML model (GradientBoosting) forecasts prices 1-6 months ahead using
       iterative autoregressive prediction with lag features.
       Falls back to seasonal + linear trend if model unavailable.

  5.23 Cross-Mandi Arbitrage         GET  /api/arbitrage/{crop_id}
       Compares latest prices for a crop across all regions.
       Identifies highest/lowest price regions and arbitrage spread percentage.

  ---- Farm Advisory ----

  5.24 Fertilizer Recommendation     GET  /api/fertilizer-recommendation/{crop_id}?n=45&p=22&k=25
       Compares soil NPK with crop requirements. Recommends specific fertilizer
       names (Urea, DAP, MOP) with exact quantities in kg/acre.

  5.25 Irrigation Scheduler          GET  /api/irrigation-schedule/{crop_id}?sowing_date=2025-06-15&rainfall_mm=800
       Week-by-week water plan for entire crop duration. Adjusts for rainfall
       and irrigation level. Shows critical water stress periods.

  5.26 Crop Calendar                 GET  /api/crop-calendar/{crop_id}?season=kharif
       Complete sowing-to-harvest timeline: land prep, sowing, fertilizer
       application dates, critical irrigation windows, pest watch periods,
       harvest window, total duration.

  5.27 Pest & Disease Risk Alerts    GET  /api/pest-alerts/{crop_id}?avg_temp_c=28&rainfall_mm=900
       Weather-based pest/disease risk assessment. Matches current conditions
       against 38 pest rules from pest_rules.csv. Returns severity, description,
       and specific management recommendations (chemical/biological).
       A planning aid, not an official weather warning.

  5.28 Rotation Planner              POST /api/rotation-plan
       Recommends optimal kharif-rabi annual crop rotation. Scores all
       season combinations by profit, risk, and diversity bonus.

  5.29 Loan/Credit Calculator        POST /api/loan-calculator
       Computes: EMI, total repayment, interest burden, DSCR (debt service
       coverage ratio), and feasibility verdict (safe/moderate/risky).

  5.30 Multi-Year Soil Projection    POST /api/soil-projection
       Projects soil NPK levels over 3-5 years based on chosen crop rotation.
       Models nutrient depletion per crop, legume nitrogen fixation, and
       fertilizer restoration (60% efficiency). Returns timeline + health trend.

  5.31 Regional Benchmark            POST /api/benchmark
       Compares farmer's actual yield and profit against regional averages.
       Shows percentile ranking and gap analysis.

  5.32 Strategy Templates            GET  /api/strategy-templates?profile=small
       8 pre-built strategy presets: conservative, aggressive, balanced,
       water-saver, organic, high-value, subsistence, diversified.
       Filterable by farmer profile (small, medium, large).

  5.33 Government Scheme Matcher     GET  /api/government-schemes?crop_id=rice&area_acres=2&season=kharif
       Matches farmer profile against 12 government schemes from
       government_schemes.csv. Filters by crop, region, area, and season
       eligibility. Returns scheme details, benefit type, and application URLs.

  5.34 Disease Screening             POST /api/disease/predict
       Preliminary visual screening of an uploaded leaf photo. Uses the
       trained classifier when available, else the HSV colour/texture
       heuristic. Returns a ranked class list plus an action plan from
       engine/disease_actions.py and disease_treatments.csv.
       Explicitly NOT a diagnosis — the disclaimer is part of the response.

  ---- Field Intelligence & Sustainability ----

  5.35 Field NDVI                    POST /api/field/ndvi
       Sentinel-2 NDVI index, canopy cover %, and a sub-field health grid
       for a drawn boundary.

  5.36 Farm Score                    POST /api/farm-score
       Blends recommendation, risk and — when a location is supplied —
       field health into a single composite score.

  5.37 Climate Alerts                POST /api/climate/alerts
       Micro-climate pest and fungal disease outbreak risk alerts.

  5.38 Carbon Credits                POST /api/carbon-credits
       An UNVERIFIED carbon-planning estimate. These are not saleable credits
       and the response says so.

  5.39 IoT Telemetry                 POST /api/iot/telemetry
       Returns a clearly labelled sample payload — there is no sensor
       integration behind this yet.

  5.40 Smart Pump Trigger            POST /api/iot/pump-trigger
       Calculates a pump-runtime recommendation. It never actuates equipment.

  ---- Farm Management ----

  5.41 Log Expense                   POST /api/expense/log
  5.42 Expense Summary               GET  /api/expense/{farm_id}?planned_budget=15000
       DISABLED. Both return HTTP 503: expense persistence requires

  5.43 Usage Config                  GET  /api/usage/config

  5.44 Usage Collect                 POST /api/usage/collect

  ---- ML Management ----

  5.46 Train All Models              POST /api/ml/train

9. KEY ALGORITHMS & FORMULAS
================================================================================

  Yield Estimation (heuristic fallback):
    yield = base_yield * soil_factor * climate_factor * irrigation_factor
    soil_factor depends on NPK adequacy ratios and pH suitability
    climate_factor depends on temperature fit and rainfall vs water requirement

  Risk Scoring:
    risk = weighted sum of drought_risk + heat_risk + flood_risk
           + price_volatility_risk + budget_risk
    Each sub-risk is 0-100 based on how far conditions deviate from optimal

  Smart Score (crop ranking):
    smart_score = 0.35 * ROI_normalized
                + 0.20 * confidence_score (100 - risk)
                + 0.15 * budget_fit
                + 0.15 * soil_health
                + 0.15 * ML_confidence_bonus

  Sensitivity Matrix:
    Simulates profit under price variations (-20%, -10%, base, +10%, +20%)
    crossed with yield variations (-20%, -10%, base, +10%, +20%)
    = 25-cell profit matrix

  Soil Health Projection:
    Per crop per season: NPK += nutrient_impact[crop]
    Legumes (pulses, groundnut, soybean) add +10 to +15 N via fixation
    Heavy feeders (sugarcane, cotton, maize) deplete -25 to -40 N
    Fertilizer restores deficit at 60% efficiency

  Loan Feasibility:
    EMI = P * r * (1+r)^n / ((1+r)^n - 1)
    DSCR = expected_profit / annual_repayment
    Verdict: DSCR >= 1.5 = safe, 1.0-1.5 = moderate, < 1.0 = risky

11. TECH STACK & ARCHITECTURE DECISIONS
================================================================================

Backend & API:
- Python 3.10+ & FastAPI Core: Chosen for high-performance async capabilities (Uvicorn), built-in data validation (Pydantic models), automatic OpenAPI (Swagger) documentation, and seamless integration with Python's data science ecosystem.

Frontend (multi-page static site, not an SPA):
- Vanilla JavaScript, HTML5, a hand-written CSS design system, & Chart.js: Chosen to maintain a strict "zero build pipeline" (No React/Node/Webpack dependencies). This ensures the app is extremely lightweight, instantaneously deployable via FastAPI static mounting, and capable of rendering complex visualizations (Chart.js Radar/Doughnut) securely offline or in low-bandwidth zones.
- Styling is deliberately framework-free. There is NO Tailwind and no CSS build step: the entire design system is ~110 KB of hand-written CSS custom properties and component classes in `frontend/style.css`. Dark mode is a `html[data-theme="dark"]` token flip, with the dark overrides injected by `toolbar.js`. The only remote stylesheet is the Google Fonts link.
- Seven separate HTML pages (index, dashboard, marketplace, gyan-seva, book-a-tractor, farm-boundary, login) each load their own `<script defer>` set; there is no client-side router.
- UI Aesthetic: "Earthy Claymorphism" was utilized to ensure a tactical, friendly, "field journal" feel that departs from sterile B2B SaaS norms, focusing deeply on farmer accessibility via hand-inlined SVG icons (no icon library) and clear typographic hierarchy (Fraunces display + Inter body).

Machine Learning & Simulation Engine:
- Scikit-Learn (RandomForest, GradientBoosting), Numpy, Joblib: Chosen because ensemble tree-based models elegantly handle complex, non-linear environmental relationships (like how N/P/K and Rainfall interplay) without requiring the massive overhead or latency of Deep Learning neural networks.

Data Persistence:
- Structured Flat CSV Files (`dataset/`): Selected for rapid Hackathon MVP iteration. Eliminates external database administration (like PostgreSQL) while using a structure directly translatable to SQL tables in the future. The Pydantic models abstract away the CSV nature from the business logic.

12. POTENTIAL EVALUATION QUESTIONS & ANSWERS
================================================================================

Q1. Why did you choose Vanilla JS over modern frameworks like React or Angular?
A1: We wanted this MVP to be as deployable and dependency-free as possible. Avoiding a node_modules build pipeline means the entire application runs natively out of a basic Python environment. It loads incredibly fast, ensuring high performance in low-connectivity rural zones, while a shared `window.MM` namespace (mm-core.js) plus per-page IIFE modules give us the state management, formatting and cross-page utilities a framework would otherwise provide. A service worker precaches the shell and `offline-simulator.js` keeps the simulate tool usable with no backend at all.

Q2. How does the deterministic Simulation Engine work alongside the Machine Learning models?
A2: The Core Engine handles deterministic logic (fixed input costs, baseline constraints, basic multipliers), while the ML models sit on top of it to introduce real-world variance. The ML algorithms predict the yield based on complex historic weather and soil feature interactions, and evaluate risk scores (Price Volatility, Pest, Drought) based on prior disaster logs. 

Q3. What exactly drives the 0-100 "Risk Score"?
A3: The risk evaluates four distinct sub-components:
1. Drought Risk (historical rainfall vs. the specific crop's exact minimum water requirement).
2. Flood Risk (excessive weather averages).
3. Pest & Disease Alerting (based on humidity/temp thresholds overlapping crop vulnerability).
4. Price Volatility (standard deviation of Mandi baseline prices over the last 5 years).
These subscores are weighted and collapsed into a 0-100 metric visualizable on our Radar Chart.

Q4. How scalable is the current CSV database approach?
A4: CSV is used strictly as a structural MVP scaffolding. Because we pipe data reads through internal helper functions and enforce strong typing via FastAPI's Pydantic Data Models, migrating to a robust PostgreSQL or MongoDB instance later requires almost zero rewrites of the business logic or frontend APIs — we only need to swap the driver in our helper methods.

Q5. How does the system generate "Smart Recommendations"?
A5: When a user enters their region and budget, the system routes these inputs through our ML-powered `recommend_crops` matrix. It simulates the profitability, calculates the predictive risk, assigns a 'Smart Score' balancing ROI against agricultural feasibility for the season, and serves the top-ranked choices back to the "Smart recommend" tool on the dashboard, where mm-enhance.js adds a per-row "Why this crop?" breakdown of the contributing factors.
