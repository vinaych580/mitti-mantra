# Phase 1 — Data Foundation

**Date:** 2026-11-11 · **Status:** Draft for owner review · **Size:** 2–3 weeks
**Fixes:** N-5, N-9, N-10; AUDIT D-3, D-4, D-5, D-12
**Depends on:** Phase 0 merged. **Dataset list:** `2026-11-11-01-datasets-acquisition.md`

## Intent

Every model limit in this project is a data limit. Most yield, weather and price rows are
generated by a seeded random script, so there is nothing true for a model to learn. This
phase replaces them with measured public data, gives every row a recorded origin, and sets
up refresh so the data stays current without manual work.

## Goals

1. A curated store with 25+ years of district yields, daily weather and 5+ years of
   weekly mandi prices for the crops in `crop_parameters.csv`.
2. Zero unlabelled synthetic rows anywhere the app or training reads.
3. Coverage grows from 30 districts to every district the sources share (target 500+).
4. Prices refresh daily and the freshness badge can honestly say "fresh".
5. One command rebuilds the curated store from raw downloads.

## Non-goals

- Retraining models (Phase 2). A hosted database for user data (Phase 3).
- Sub-district (village or plot) data.

## Anti-goals

- Filling gaps with generated values. A missing district-crop-year stays missing.
- Committing gigabytes to git.

## Constraints

- Vercel function bundle is size-capped; the served data must stay small (target under
  40 MB). Training data lives outside the bundle.
- The app must still start from a fresh clone with no downloads (small committed sample).

## Design

### 1.1 Layout

```
data/
  raw/        as downloaded, immutable, gitignored
  staged/     cleaned, canonical keys, one Parquet per source, gitignored
  curated/    joined analytical tables (Parquet), gitignored; published as a release asset
dataset/      what the app serves: small CSV/SQLite, committed
  serving.sqlite     read-only, built from curated/
  *.csv              kept for the 30 pilot districts as the fresh-clone fallback
pipelines/
  sources/<name>.py  one module per source: download(), stage()
  build_curated.py
  build_serving.py
  validate.py
  manifest.json      content hashes, row counts, source versions
```

`data_ingestion/` is retired: its working fetchers move to `pipelines/sources/`, and
`etl_pipeline.py`, `feature_pipeline.py` and the random-valued `soil_health_card.py` are
deleted (AUDIT D-3, D-4).

### 1.2 Canonical keys

- `district_id` = LGD district code. A mapping table carries source spellings, former
  names and parent districts for splits (Telangana 2016, others), with the year range
  each mapping holds.
- `crop_id` stays as today, with an alias table from each source's crop names.
- `season` ∈ kharif, rabi, zaid, annual, perennial, lower case everywhere.
- The 30 existing `region_id` values map one-to-one onto `district_id`; the old ids keep
  working through an alias so saved plans do not break.

### 1.3 Curated tables

| Table | Grain | Key columns | From |
|---|---|---|---|
| `yield_dcy` | district, crop, season, year | area_ha, production_t, yield_kg_ha, yield_kg_acre | A1, cross-checked with A2 |
| `weather_daily` | district, date | rain_mm, tmin, tmax, tmean, rh, solar, wind | A4, A5 |
| `weather_stage` | district, crop, season, year | rain and heat by growth stage, dry-spell max, onset date, GDD | derived with A14 |
| `price_weekly` | mandi, crop, week | modal, min, max, arrivals_t, n_days | A3, C1 |
| `price_district_weekly` | district, crop, week | arrival-weighted modal price | derived |
| `soil_district` | district | pH, OC, N, P, K, texture | A10, A11 |
| `irrigation_share` | district, crop, year | irrigated fraction | A12, A2 |
| `ndvi_16d` | district, date | mean NDVI over cropland | A13 |
| `cost_state_crop` | state, crop, year | cost A2, A2+FL, C2 and components | A7 |
| `msp` | crop, year, season | msp_per_quintal | A8 |

Every table carries `source`, `source_version`, `fetched_at`, `licence`, `is_synthetic`.

### 1.4 Validation gates (`pipelines/validate.py`)

The build fails when any of these is violated:

- Units and ranges per column (yield within crop-specific physical limits, rain ≥ 0,
  price > 0, pH 3–10).
- No duplicate keys. No year gaps inside a series longer than a stated tolerance.
- A1 and A2 agree within 15% where both exist; disagreements are listed in a report.
- `is_synthetic` is false for every row in `serving.sqlite` outside the fallback CSVs.
- Row counts do not fall more than 5% from the previous manifest without an override flag.

### 1.5 Serving

- `utils/csv_cache.py` gains a sibling `utils/store.py` with the same call shapes
  (`load`, `index_by`) backed by `serving.sqlite`; callers move table by table. CSV remains
  the fallback if the SQLite file is absent.
- Serving holds: last 10 years of yields, 30-year climate normals plus last 3 seasons of
  stage weather, last 104 weeks of district prices, soil, irrigation, costs, MSP.
- `utils/provenance.py` reads `fetched_at` and `is_synthetic` from the store.

### 1.6 Refresh on Vercel

Staying on Vercel means no long-running worker, so refresh runs in **GitHub Actions**:

| Job | Schedule | Does |
|---|---|---|
| `prices-daily` | daily | fetch C1, append to `price_weekly`, rebuild serving prices, publish |
| `weather-weekly` | weekly | fetch C3 actuals, update stage features for the running season |
| `yields-yearly` | manual | re-download A1 |
| `forecast` | not stored | the API calls Open-Meteo (C2) on request with a 6-hour cache |

"Publish" = upload the new `serving.sqlite` to Vercel Blob (or a release asset) and
trigger a redeploy hook. The function reads it from the bundle; a Blob read at cold start
is the fallback when the bundle is older than the Blob's manifest.

### 1.7 Live mandi path (N-10)

- Verify the data.gov.in resource with a real key. If the hardcoded resource is gone, use
  the variety-wise daily resource or CEDA.
- Commodity mapping covers every crop in `crop_parameters.csv` or records "no mandi
  series" for it.
- Filter by state and district, take the latest date, weight by arrivals.
- Prices reach the app through the scheduled job, not through a per-request upstream call.

### 1.8 Region picker data

`GET /api/v1/districts` returns state, district, centroid, and which datasets cover it,
so the UI (Phase 4) can say "yields and weather available; no mandi series".

## Work order

4. Prices history and the daily job. 5. Costs, MSP, soil, irrigation. 6. NDVI.
7. Serving store and `utils/store.py`. 8. Remove synthetic rows. 9. Tests for each

## Acceptance

- `python -m pipelines.build_curated && python -m pipelines.validate` passes from raw.
- `yield_dcy` ≥ 150,000 rows across ≥ 500 districts and ≥ 25 years.
- `price_district_weekly` covers ≥ 20 crops for ≥ 5 years.
- `/api/data-freshness` reports mandi prices under 7 days old on the deployed site.
- `grep` finds no call to `random` in any module that writes data.
- Bundle size reported in the PR and under the cap with at least 30% headroom.

## Left to the builder

Parquet library choice (pyarrow is the default), exact SQL schema, the growth-stage
boundaries per crop where A14 is silent (document each assumption in the table).

## Risks

- A3 volume and rate limits: download once on a workstation, not in CI.
- District splits can double-count; rely on the mapping table and the A1-vs-A2 check.
- Some crops (cashew, coffee, tea) have thin mandi data; they keep price bands from
  `crop_parameters.csv`, labelled as reference bands.
- Licence terms differ per source; the manifest records the licence, and the app's
  sources page lists each one with attribution.
