# Zaid Season Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete zaid-season support across the app: a small real zaid crop catalog, real zaid weather data for every region, the ML season vocabulary fix, and the frontend touchpoints still missing a Zaid option.

**Architecture:** Add three zaid crops to the crop-parameters seed dataset with matching crop-calendar entries (both consumed automatically by the chatbot, recommend engine, and calendar API since they read `crop_parameters.csv` directly). Extend the existing `refresh_weather_seed.py` script with a zaid season window and run it once to backfill real Open-Meteo data. Add "zaid" to the ML season-encoder vocabulary (without retraining — see Task 3's note). Fill in the frontend season selectors and parsers still missing zaid.

**Tech Stack:** Python (FastAPI backend, pandas-free CSV handling via `utils/csv_cache`), vanilla JS frontend, pytest.

**Spec:** [docs/superpowers/specs/2026-09-11-zaid-season-completion-design.md](../specs/2026-09-11-zaid-season-completion-design.md)

## Global Constraints

- Do not retrain `ml/recommend_model.joblib` / `ml/yield_model.joblib` in this plan — a separate session is mid-retrain on these same models for an unrelated accuracy-fix plan in a different worktree; a second retrain here would be discarded when that branch merges and retrains again.
- Do not add `yield_history.csv`, `msp_prices.csv`, or `mandi_prices.csv` zaid data — no real historical data exists to backfill from, and fabricating it is out of scope (spec §8).
- Do not expand the zaid crop catalog beyond the 3 crops below, or audit other crops for possible zaid variants beyond the existing `moong = Kharif/Zaid` tag.
- The full pytest suite must stay green after every task's final step. Run `python -m pytest -q tests` from the repo root (no venv prefix needed in this repo's normal setup — if `python` doesn't resolve to the project's venv, use `venv/Scripts/python.exe` on Windows).
- Match this repo's existing code style: plain prose comments explaining *why*, not `// FIX (ID)`-style tags (those IDs belong to `AUDIT_REPORT.md` findings this work doesn't originate from).

```python
def _season_range(season: str, year: int) -> tuple[date, date]:
    """Kharif `year` runs Jun-Oct of `year`; rabi `year` runs Nov `year` to
    Mar `year+1` -- matching the existing CSV's agricultural-year convention,
    where "kharif Y" is immediately followed by "rabi Y" for the same crop
    year. Zaid `year` runs Mar-May of `year` -- the summer season between
    rabi's harvest and the next kharif's sowing, entirely within one
    calendar year unlike rabi."""
    if season == "kharif":
        return date(year, 6, 1), date(year, 10, 31)
    if season == "rabi":
        return date(year, 11, 1), date(year + 1, 3, 31)
    if season == "zaid":
        return date(year, 3, 1), date(year, 5, 31)
    raise ValueError(f"unknown season: {season}")
```
